# Готовая дизайн-схема: Material 3 Expressive + мягкая глубина + human-centered UX

Название для макетов: «Ладно». Образ: спокойный помощник по расходам, ясные числа, тактильные округлые поверхности, живые акценты. Human Design трактуется как человекоориентированный UX: доступность, прозрачные расчёты, контроль и спокойные формулировки.

## Система

Material 3 Expressive задаёт формы, иерархию, навигацию, компоненты и выразительное движение. Neumorphism добавляет глубину у обзорной budget hero-карточки и нескольких контейнеров. Поля ввода, кнопки и строки обязаны оставаться различимыми по контрасту/границам: состояние не выражается только тенью. Для тёмной темы и режима высокого контраста мягкие тени можно убрать.

| Токен | Light | Dark |
|---|---|---|
| background | `#F5F4F0` | `#121716` |
| surface | `#FFFFFF` | `#1D2422` |
| primary | `#00574F` | `#83D5C6` |
| onPrimary | `#FFFFFF` | `#003A34` |
| secondary container | `#E6DFF7` | `#3C3450` |
| onSurface | `#172522` | `#E4ECE7` |
| onSurfaceVariant | `#4F5F59` | `#B8C8C0` |
| error | `#B3261E` | `#FFB4AB` |

Это проектные токены, не заявление о проверке всех возможных пар. Для кнопок primary/onPrimary и обычного текста onSurface/background проверить WCAG contrast автоматически. Другие состояния проходят отдельный аудит. Dynamic color опционально; брендовая палитра — default, одинаковая на Android/веб.

Шрифт: локально поставляемый Roboto/Roboto Flex с кириллицей и лицензией. Табличные цифры для сумм. Сетка 4/8 dp; page padding 16–24 dp; card radius 24–32 dp; controls radius 12–20 dp; минимум touch target 48×48 dp. Анимации 160–320 ms с выразительными spring только там, где они поясняют действие; reduce motion отключает перемещения и масштабирование. Доступный фокус, hover/pressed состояния в вебе.

Neumorphic light surface: мягкая нижняя тень и слабый верхний свет, без размытия текста. Не накладывать тени на каждую строку. Графики используют 4–6 различимых цветов, подписи и числовую таблицу; отрицательные значения не скрываются. Поддержать screen readers и увеличенный шрифт до 200% без обрезания критических сумм.

## Навигация и адаптивность

Android compact: нижняя навигация «Обзор», «Операции», «План», «Анализ», «Ещё». Счета, карты, источники, настройки и admin находятся в «Ещё», часто используемые счета доступны из фильтров. FAB добавляет операцию; на экране плана primary action редактирует план. На medium — navigation rail. На wide — sidebar и master/detail, несколько колонок с ограниченной шириной контента. Breakpoints определяются доступным размером окна, не строкой user agent.

Веб: URL для основных разделов, browser back/forward, клавиатурный фокус, таблица операций, боковая панель подробностей. Мобильный экран не просто растягивается на desktop.

## Тексты и достоверность

«Осталось по плану» вместо «Баланс». «Можно потратить по ориентиру» вместо обещания наличия денег. Никаких «общий баланс», «баланс карты», «доступно на счетах», CVV и полных номеров карт. Last4 только для различения карт, необязательное поле. Карточка карты — компактный идентификатор, а не большой фотореалистичный пластиковый объект.

Offline status: «Нет сети · изменения сохранены на устройстве». Pending sync: «5 изменений ждут отправки». Session expired: «Нужен новый код для синхронизации»; локальный ввод остаётся доступен. Admin offline: «Для создания приглашения подключитесь к сети». Budget warning: «План превышен на 700 ₽. Перераспределить категории?»

Синтетический dataset для макетов: 17.11.2026 начало дня; месячный лимит 32 000 ₽; факт до 17-го 18 000 ₽; общий остаток 14 000 ₽; резерв 2 400 ₽; дневной ориентир 828,58 ₽; остаток части недели 17–22 ноября 4 971,44 ₽. Категории actual: жильё 9 600, продукты 5 000, транспорт 1 000, подписки 1 400, прочее 1 000 = 18 000 ₽. Нет неоплаченных обязательств в этом конкретном dataset. Для показываемых карточек иных состояний использовать отдельный явно описанный dataset, не менять числа в одном и том же сценарии.

Банки: ОТП Банк → счёт «Повседневный» → карты «Основная •1234», «Дополнительная •5678». Альфа-Банк → счёт «Покупки» → «Карта •9876». Названия, цифры и суммы вымышленные. Переключение карты не меняет суммарный расход задним числом.

## Реализация схемы непосредственно в Compose

`DESIGN_TOKENS.json` содержит машинные токены. `design/mobile_screens.svg` показывает композицию Обзора, Операций и Плана.

Основная модель Sol 6.1 medium самостоятельно завершает недостающие решения по композиции в пределах заданной системы. Luna ui_worker реализует назначенные компоненты; композицию, согласованность и приёмку проверяет основная модель. Это не добавляет AI-сервисы в само финансовое приложение.

Сначала реализуются tokens и общие компоненты, затем Обзор/Операции/План/Счета, затем остальные сценарии. Визуальные fixtures допустимы в debug/demo, production UI получает данные из локальных repositories. Макет не вставляется растровой картинкой: компоненты реализуются Composable с реальными действиями.

Шифрование: показать «Данные зашифрованы» с понятным описанием серверной копии и устройствами. Экран ключа восстановления — обязательный. Offline-first не означает отсутствие сервера: локальные данные отправляются в зашифрованном виде, когда есть сеть.


## Точная композиция основных экранов

### Обзор

Порядок сверху вниз: app bar «Обзор» и дата/период; независимый sync status; segmented control День/Неделя/Месяц; hero budget card; две малые карточки «На сегодня»/«Резерв»; список последних операций; bottom navigation. Основная кнопка добавляет операцию, а не меняет бюджет. Источники и состояние доступа к уведомлениям доступны в «Ещё»; при реальной проблеме появляется спокойная строка действия.

Hero: верхняя подпись периода, сумма 40–48sp с tabular figures, строка «Потрачено 18 000 из 32 000 ₽», прогресс 56,25%, ссылка «Как рассчитано». У hero мягкая объёмная поверхность; у остальных блоков обычный Material surface. Резерв 2 400 ₽ показывается отдельно, без объявления свободными деньгами на карте.

| Выбранный период | Подпись hero | Сумма в демонстрационном сценарии | Контекст |
|---|---|---|---|
| День | Осталось по ориентиру сегодня | 828,58 ₽ | 17 ноября, начало дня; факта сегодня ещё нет |
| Неделя | Осталось по ориентиру до воскресенья | 4 971,44 ₽ | Только оставшиеся 17–22 ноября; не весь полный недельный бюджет |
| Месяц | Осталось по плану | 14 000 ₽ | Ноябрь; включает 2 400 ₽ защищённого резерва |

Карточка «На сегодня» не вычитается из месячного остатка как дополнительная сумма. Если пользователь уже находится в периоде День, вторичная карточка меняется на месячный контекст. Прогресс для day/week рисуется только при наличии корректного плана/факта этого периода; нельзя использовать месячные 56,25% под дневной подписью.

### Операции

App bar с «Добавить» → поле поиска → chips «Период», «Счета и карты», «Категории» и кнопка всех фильтров → итог выбранной выдачи → список по датам. Строка: иконка 40dp слева, merchant/описание 16sp, категория/счёт/карта 12–14sp, справа точная сумма 16–18sp. Тип операции дополнительно выражается знаком и текстом, не одним цветом. Наведение в web и нажатие открывают детали; отметка review доступна отдельно.

Фильтры на compact открываются как bottom sheet с прокруткой и закреплёнными «Сбросить / Показать N». На expanded — боковая панель 320dp. Перед закрытием сохранить черновик локально; применить только по явному нажатию. Итог и число строк принадлежат одному ExpenseQuery. Переводы можно видеть в списке, но они помечены «Не входит в расходы».

### План

Header «План» и выбор месяца → День/Неделя/Месяц → общий предел и факт → защищённый резерв → категории с plan/actual/remaining → обязательства → действие перераспределения. Показывать план в каждой строке явно: прогресс не заменяет числа.

| Категория | План, ₽ | Факт, ₽ | Осталось, ₽ |
|---|---:|---:|---:|
| Жильё | 9 600 | 9 600 | 0 |
| Продукты | 10 000 | 5 000 | 5 000 |
| Транспорт | 2 000 | 1 000 | 1 000 |
| Подписки | 1 400 | 1 400 | 0 |
| Прочее | 6 600 | 1 000 | 5 600 |
| Защищённый резерв | 2 400 | 0 | 2 400 |
| Всего | 32 000 | 18 000 | 14 000 |

«Перераспределить» открывает редактор с изменением allocations. Внизу видны общий лимит, распределено/нераспределено и изменения сегодняшнего ориентира. Сохранение атомарно локально. Уменьшение allocation ниже факта разрешается только с понятным предупреждением о перерасходе; факт не меняется автоматически.

### Банки, счета и карты

Банк — заголовок группы с иконкой, ниже счёт с валютой и количеством карт, внутри компактные card chips/строки. Никаких сумм на карточке счёта. Основные действия — добавить счёт и привязать карту; смена иконки доступна из редактора. Видимость архивных — отдельный фильтр. Снятие карты с активного использования не удаляет операции.

Редактор карты: имя, выбранный счёт, last4 необязательно, иконка. При смене счёта текст «Новая привязка применяется к будущим операциям». Перенос истории — отдельное осознанное действие с количеством затрагиваемых операций. Поля номера счёта/PAN/CVV отсутствуют.

### Источники и проверка

Первый блок объясняет доступ и показывает статус Android listener. Каждый источник — приложение, назначенный профиль, основные счета, enabled, дата последнего обработанного события и число pending. Дополнительные технические поля скрыты в «Дополнительно». Веб управляет синхронизируемыми правилами, но не показывает кнопку выдачи Android-разрешения.

Проверка показывает причину первой строкой: «Не удалось определить карту» или «Возможное повторение». Далее — извлечённая сумма/время, доступный маскированный фрагмент и поля исправления. При подозрении на дубль две операции сравниваются рядом на wide или последовательно на compact. Primary «Подтвердить», secondary «Игнорировать»; объединение только по явному действию.

### Вход, восстановление и администрирование

Вход — одна задача на экран: код приглашения, вставить/сканировать, продолжить. Для нового vault следующий экран сохраняет recovery key; для второго устройства — импортирует его. Смысл двух секретов объясняется отдельными подписями. Ошибка сессии уже активированного устройства не превращает весь интерфейс в экран входа.

Admin — отдельный маршрут в «Ещё» только для ADMIN. На compact tabs Приглашения/Пользователи/Устройства/Журнал прокручиваются; на wide — горизонтальные вкладки и таблица. Создание приглашения — отдельная форма. Код показывается один раз после успешного online ответа; clipboard/QR по нажатию. Offline оставляет список видимым с датой обновления и блокирует только серверные действия с объяснением причины.

| Ширина | Навигация | Контент | Формы и детали |
|---|---|---|---|

## Состояния и поведение

| Состояние | Отображение | Доступные действия |
|---|---|---|
| Нет данных | Короткое объяснение, «Добавить операцию»/«Настроить источник» | Все локальные настройки |
| Нет совпадений фильтра | «По этим фильтрам операций нет» | Сбросить фильтры |
| Нет сети | «Нет сети · изменения сохранены на устройстве» | Ввод/редактирование/анализ полностью доступны |
| Есть pending | Количество и время последней sync | Работать дальше; повторить sync при сети |
| Нужен новый код для sync | Неблокирующая строка со ссылкой входа | Локальная работа сохраняется |
| Local commit не удался | Явная ошибка у формы, черновик сохранён в памяти | Повторить/экспортировать; не показывать успех |
| Storage quota | Объяснение, что новая запись не сохранена | Экспорт, очистка только подтверждённых ненужных кешей |
| Конфликт | Две версии, различающиеся поля | Выбрать/объединить, без молчаливой потери |
| Текст уведомления скрыт | «Не удалось прочитать данные операции» | Ручной ввод, диагностика |
| Admin offline | Последний полученный список с датой | Просмотр; generation/revoke требуют сеть |

Никаких постоянных модальных предупреждений поверх контента из-за отсутствия сети. Loading spinner допустим при первом раскрытии vault/проекции с прогрессом; уже доступные данные не исчезают при refresh. Ввод суммы использует locale-aware decimal keyboard, валидируется без молчаливого округления.

## Движение, доступность и визуальная приёмка

Нажатие 160ms, смена панели около 240ms; поддерживаемая Expressive spring применяется к выбранному состоянию, а не ко всем числам одновременно. Суммы обновляются без «счётчика денег», который затрудняет чтение. Reduce motion убирает spatial transitions.

Контрольные размеры: 360/412dp compact и 1024/1440 logical px wide, дополнительно 200% шрифт. Реально проверить light/dark, focus order, TalkBack labels, значения progress, доступные table rows, отсутствие дублированных announce amounts. Screen reader должен прочитать «Осталось по плану за ноябрь: 14 тысяч рублей», а не отдельно десяток декоративных цифр.

Приёмка: один fixture dataset даёт одинаковые суммы на обзоре, плане, операциях и аналитике; offline ввод остаётся видимым после перезапуска; видимые иконки доступны из локального storage; admin элементы отсутствуют у USER; все крупные кнопки имеют понятное действие и обратную связь.
