# План: день, неделя, месяц

Периоды бюджета — продуктовая функция из `docs/BUDGET_RULES.md`. Здесь отдельно расписан план разработки. Оценки — рабочий ориентир для одного разработчика, не гарантия готовности. Важнейшие неизвестные — реальные банковские форматы и Wasm/crypto/storage интеграция.

## Первый день: доказать осуществимость

6–9 часов сосредоточенной работы, без обещания полноценного приложения.

| Время | Задача | Результат |
|---|---|---|
| 0–2 ч | T01 | Android, web и Kotlin backend собираются на проверенных версиях |
| 2–4 ч | T02 | Listener получает synthetic push по фильтру; ограничения реального телефона зафиксированы |
| 4–6 ч | T03 | Android/JVM и Wasm обмениваются encrypted payload, wrong key/tag отклоняются |
| 6–9 ч | Начало T04 и уточнения | Money/account/card contracts, список реальных blockers, STATUS |

Если за день не собрался Wasm crypto adapter или реальный listener не получает текст, это меняет следующий план. Не тратить этот день на все экраны и декоративные тени.

## Первая неделя: рабочая локальная альфа

Около 35–50 часов, если первый день не выявил крупного blocker. Это интенсивная неделя, не семь вечеров по часу.

| День | Задачи | Критерий |
|---|---|---|
| 1 | T01–T03 | Подтверждённый стек, notification/crypto spikes |
| 2 | T04, T05 | Domain без балансов; реальные invite/device/session endpoints |
| 3 | T06, T07 | Encrypted local storage, outbox, recovery key |
| 4 | T08, T09 | Дизайн-система; активация и offline restart |
| 5 | T10, T11 | Счета/карты/иконки и ручные операции офлайн |
| 6 | T12, T13 | Durable inbox и первый experimental/реально проверенный профиль |
| 7 | T14, начало T15 | Нет повторного счёта push; проверка неоднозначных операций; budget engine |

Результат недели — локальная альфа Android и веб после активации, с обязательной записью в outbox; полный двухсторонний sync можно ещё не объявлять законченным. Админ API уже нужен для активации, но красивый отдельный admin screen завершается позже. Бюджеты и дизайн не выдаются за завершённые, пока не выполнены соответствующие acceptance tests.

## Месяц: синхронизированная личная бета

Ориентир 120–170 часов вместе с первой неделей. При 2–3 часах в день разумнее ожидать 6–10 недель. Если времени меньше, не отключать шифрование или offline сохранность ради формального срока; переносить декоративную полировку и число поддерживаемых банковских форматов.

| Неделя | Задачи | Результат |
|---|---|---|
| 1 | T01–T14, начало T15 | Локальная альфа: invite, vault, счета/карты, операции, listener/review |
| 2 | Завершить T15, T16–T19 | Полные day/week/month бюджеты, категоризация, encrypted Android ↔ web sync, конфликты |
| 3 | T20–T24 | PWA offline reload, обзор/графики, рекомендации, admin screen, import/export/recovery |
| 4 | T25–T28 | Доступность, измерения, device tests, backup/restore, исправления, beta artifacts |

Независимые изменения UI и тестовых данных можно выполнять параллельно после согласования контрактов. Изменения общей сборки и схемы БД согласуются отдельно.

## Критерий беты

- Первый вход только по admin invitation; ADD_DEVICE подключает тот же vault, а не создаёт второй набор расходов.
- Данные всех долгоживущих сущностей находятся локально и синхронизированы на сервере зашифрованными; сервер не знает recovery key.
- После активации приложение работает без сети и при истёкшей сетевой сессии; очередь переживает restart.
- Веб после первого запуска открывается offline и хранит операции/иконки; quota и storage reset обработаны честно.
- Несколько карт могут ссылаться на один счёт; фильтры по банку/счёту/карте работают; банковских балансов нет.
- Один push не считается повторно; две похожие покупки не исчезают; unknown format и unknown card разрешаются через review.
- Бюджеты day/week/month соответствуют одной точной модели; transfers/refunds/fees классифицированы правильно.
- Синхронизация выдерживает потерю ответа, два устройства и конфликт; выбранное пользователем решение не теряется.
- Новый клиент реально восстанавливает данные с recovery key; key loss policy объяснена.
- Отдельный admin screen выпускает/отзывает коды и сессии с server RBAC; не читает расходы других пользователей.
- Есть offline CSV/JSON export и encrypted backup, проверенное восстановление, сборки Android/web и честная матрица поддержки банков.

Публикация в магазинах, независимый криптоаудит и массовое подключение всех банков не входят в обещание месячной личной беты. Это не отменяет реализацию перечисленных продуктовых функций; граница касается масштаба проверки и распространения.
