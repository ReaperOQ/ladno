# ADR T04: доменная модель и границы проверки

18.11.2026. Принято.

Общие сущности живут в `shared/domain`, используют Kotlin, kotlinx.serialization/datetime и Flow. Идентификаторы — проверенные UUID-строки. Sync metadata содержит revision, tombstone и локальное состояние; archivedAt справочников отделён от удаления. Порт удаления справочника допускает только tombstone неиспользуемой записи, физическое удаление не предоставляется.

Money — signed Long minor units с фиксированной precision поддерживаемых валют. Сумма операции строго положительна, направление задаёт kind. Строковый decimal JSON сохраняет точность за пределами JavaScript safe integer. Ввод major units — без группировки и символа валюты, с точкой или запятой; лишняя precision отклоняется даже для нулей. Деление требует явного режима округления. FX и неявного суммирования разных валют нет.

Transaction хранит собственный accountId. `validateNewSources` проверяет текущую card→account привязку для новой операции или явной смены источника. Эту проверку нельзя применять к неизменённому источнику исторической операции: карта могла сменить счёт. Архивирование не переписывает операции и не исключает их из расходов; новые назначения архивных счетов/карт/категорий запрещены. При чтении истории проверяются существование ссылок и валюта сохранённого счёта, без требования его активности или текущей привязки карты.

Transfer — один агрегат между разными счетами одной валюты, оба push могут быть evidence. Комиссия — отдельный expense. Refund имеет обязательные splits и необязательную ссылку на исходный расход; связанный возврат сохраняет категории исходного расхода и ограничивается исходной суммой с учётом других живых возвратов. Без связи категория всё равно обязательна. Дата возврата независима от даты покупки. ReviewStatus не подменяет kind; pending/ignored/excluded/tombstones дают нулевой budgetImpact.

BudgetMonth не допускает двойного распределения сверх expenseLimit: категории и резерв суммируются вместе, остаток доступен как unallocated. PlannedPayment хранит отдельные покрытия, включая частичные, а remaining не становится отрицательным. Ожидаемый платёж сам по себе не является расходом; календарный schedule здесь — конкретная dueDate, генерация повторений относится к последующему движку.

`LocalLedger.mutate` — контракт атомарной локальной записи вместе с encrypted outbox. Проверки ссылок и полных refund/payment aggregates выполняет реализация хранилища внутри сериализованной транзакции. Конкурентный sync требует повторной проверки и quarantine конфликтов. LocalEntityStore.save вне этой границы недопустим. В T04 нет in-memory production persistence, Room/IndexedDB, сетевых endpoints или серверной обработки plaintext; адаптеры последуют в T06. IconAssetRef хранит только идентификатор encrypted blob, а не URL или открытый hash.
