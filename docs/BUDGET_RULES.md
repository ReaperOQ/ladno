# Правила бюджета

## Семантика

Бюджет ограничивает расходы. Банковские балансы не вычисляются, не запрашиваются и не отображаются. Счета/карты нужны для происхождения операции и фильтров. Лимит не увеличивается из-за добавления карты, внутреннего перевода или дохода без явного изменения плана.

Месячный план содержит:

- `M` — предел расходов;
- `R` — защищённый резерв на непредвиденное;
- `C[i]` — распределение по категориям, включая обязательства;
- правило переноса; по умолчанию закрытый месяц не меняет лимит следующего автоматически.

При полностью распределённом плане `sum(C) + R = M`. Нераспределённые деньги допустимы и видны отдельно. Нельзя зарезервировать одну сумму дважды: обязательства входят в соответствующую категорию, а резерв — отдельный bucket. Goal contributions находятся вне потребительских расходов; для ограничения доступного лимита пользователь явно уменьшает M.

`S` — фактические confirmed расходы минус confirmed возвраты по датам текущего периода. Transfers, income, ignored, pending и excluded операции не входят в S. Возврат не создаёт доход: это уменьшение net расходов с отдельным gross/refunds представлением. Допустим отрицательный net периода, например возврат прошлой покупки; UI показывает знак без молчаливого обнуления.

`monthlyRemaining = M - S`. Перерасход сохраняется отрицательным и показывается явно.

## Обязательства и дневной ориентир

`F` — сумма ещё не покрытых обязательств месяца. Каждое PlannedPayment после связывания с расходом уменьшает F; фактический расход увеличивает S. Обе записи изменяются одной логической операцией. При частичной оплате F уменьшается только на покрытую сумму; при большей оплате разница отражается в actual, а F не становится отрицательным.

`Rremaining` — оставшаяся защищённая часть резерва. Трата резерва требует отметки; иначе резерв не исчезает автоматически.

На начало календарного дня:

`V = M - S_before_today - F_remaining - Rremaining`

`D = число календарных дат от сегодня до конца месяца включительно`

Если V > 0, распределить V по D дням в целых minor units. `base = V / D`, `remainder = V % D`; первые `remainder` дат получают на копейку больше. Если V <= 0, разрешённая повседневная доля равна нулю, но дефицит V показывается отдельно.

Сегодняшние переменные расходы вычитаются из сегодняшней доли. Пришедший в течение дня подтверждённый возврат добавляется к доступному ресурсу с объяснением; изменение обязательств/плана запускает явный перерасчёт. Не пересчитывать дневную долю после каждой обычной покупки так, чтобы часть сегодняшнего перерасхода незаметно переносилась на будущие дни.

При переходе на следующий день неистраченная/перерасходованная сумма естественно включается в новое распределение оставшегося V. Для фиксированного пользовательского cap действует отдельное правило переноса, по умолчанию переноса нет. Дополнительный cap ограничивает трату сверх ориентира; ориентир остаётся рекомендацией. Можно вручную перераспределить сумму с будущих дней с показом влияния.

## Неделя

Неделя по умолчанию Пн–Вс, настройка влияет на будущие расчёты. Месяц не делится на 4. Недельный ориентир — сумма дневных плановых долей дат внутри недели. Для текущей недели отдельно показываются полный недельный план, факт и остаток от текущего дня.

На стыке месяцев суммируются доли из двух месячных планов. Если следующий месяц ещё не создан, показывается только покрытая часть с подписью, а не нулевой лимит или выдуманный план. Независимый weekly cap допускается; одна и та же операция учитывается в месячном и недельном отчёте, но не вычитается из общего ресурса дважды.

## Категории и cash flow

Дневной ориентир общего лимита не обещает наличие денег на карте. Категорийный лимит — дополнительный срез. Если общая дневная доля 800 ₽, но в категории «Кафе» осталось 200 ₽, UI показывает оба ограничения. Изменение классификации пересчитывает категории, но общий actual не меняется. Split expense распределяется по категориям один раз.

Внутренний перевод и погашение кредитной карты исключены из расходов; комиссия — отдельный expense. Карта и привязанный счёт не создают две копии расхода. Возврат получает исходную категорию, если связь известна, иначе требует выбора категории. Перерасход прошлого месяца не переносится незаметно: при rollover показывается расчёт нового плана.

## Пример для UI и тестов

Дата: 17.11.2026, начало дня, зона Europe/Moscow. M = 3 200 000 копеек, S до 17-го = 1 800 000, F = 0, Rremaining = 240 000. Дней D = 14. V = 1 160 000. Первые два дня получают 82 858 копеек, следующие двенадцать — 82 857.

- Общий остаток расходов по плану: 14 000 ₽.
- Защищённый резерв: 2 400 ₽.
- Сегодня доступно по ориентиру: 828,58 ₽.
- 17–22 ноября: 4 971,44 ₽; это оставшиеся 6 дней календарной недели.
- 17–23 ноября: 5 800,01 ₽; это скользящий горизонт 7 дней, отдельная подпись.
- Покупка 300 ₽ сегодня оставляет 528,58 ₽ сегодняшнего ориентира и 13 700 ₽ месячного остатка.

Суммы на экранах можно округлять до целого рубля только для компактной карточки; рядом/по нажатию доступно точное значение. Округление UI не меняет underlying budget.

## Обязательные проверки

Февраль 28/29 дней; месяц 30/31 день; неделя на стыке месяца/года; DST в другой зоне; отсутствие следующего плана; нулевой лимит; отрицательный остаток; копеечный remainder; частичная оплата обязательства; отмена связи с оплатой; возврат прошлого месяца; split/category change; большая сумма с overflow; валюта != RUB; ручной cap; rollover; сегодняшний расход не распределяется повторно на будущие дни.
